# lhg-mp-budget：预算分配三框架

> ⚠️ **合规声明（先读）**：本 skill 是**预算规划**方法论，**不构成任何投资建议**；涉及投资决策请咨询持牌专业人士。
>
> 目标：把"这个月别乱花钱"变成每个分类的金额上限。核心纪律：**先选框架后填数，合计必须 100%**。

## 1. 何时使用

- 用户说"帮我做个月度预算"→ 全流程
- 用户已经有上月账本，想基于实际数定预算 → 重点跑第 4 步（按实际微调）
- 用户月光、想强制储蓄 → 推荐"先储蓄后消费"的框架顺序（第 3 步）

## 2. 三个框架速览

| 框架 | 切法 | 适合谁 | 一句话差异 |
|---|---|---|---|
| 50/30/20 | 必要50% / 想要30% / 储蓄20% | 大多数上班族 | 最简单，先保证储蓄比例 |
| 六罐子 | 必要55% / 长期储蓄10% / 教育10% / 玩乐10% / 大额支出10% / 赠与5% | 想精细化、爱存钱的人 | 把"储蓄"拆成多种用途，玩乐有专门额度 |
| 零基预算 | 每分钱指定去向，月末结余归零 | 自控力强、想极致优化的人 | 最细，但维护成本最高 |

**选用原则**：默认推荐 50/30/20（小白友好）；用户说"太粗了"再上六罐子；用户说"我要抠到极致"才上零基预算。不许一上来就推最复杂的。

**框架切换信号**：用户用 50/30/20 三个月后说"灵活消费里钱总是不够分"，就是升级六罐子的信号；用户说"我想知道每一分钱去哪了"，才是零基预算的信号。别提前升级。

## 3. 框架落地四步

### 第一步：定基数
用税后月收入做基数。收入不稳定的取近 6 个月平均 ×0.8（保守口径，见 lhg-mp-track）。

### 第二步：套框架出初版
按选定框架算出每个大类的金额。例如月入 18000 用 50/30/20：
- 必要支出：9000
- 灵活消费：5400
- 储蓄：3600

### 第三步：按上月实际微调
对照上月账本（有 lhg-mp-track 的快照最好）：
- 某类上月实际远超框架额度（如餐饮花了 4000，框架只给 3000）→ 两种处理：**压缩**（定 3200 并给 3 条具体压缩动作）或**调框架**（从"灵活消费"里挪额度，储蓄部分不动）。
- **铁律**：调来调去，储蓄部分不许被压缩到 10% 以下；低于 10% 必须明确提醒用户。

### 第四步：拆到可执行的分类上限
把大类拆成用户实际会花的分类，每类一个金额上限。示例（月入 18000，50/30/20）：
- 住房 5000 / 餐饮 2200 / 交通 800 / 日用 1000（必要 9000）
- 购物 2000 / 社交聚餐 1500 / 玩乐 1900（灵活 5400）
- 应急金 1600 / 长期目标 2000（储蓄 3600）

每个分类标注"预警线"（上限的 90%）：花到预警线就提醒，花超上限标红。

## 4. budget.json 格式

```json
{
  "monthly_income": 18000,
  "frame": "50-30-20",
  "categories": {
    "住房": 27.8,
    "餐饮": 12.2,
    "交通": 4.4,
    "日用": 5.6,
    "购物": 11.1,
    "社交聚餐": 8.3,
    "玩乐": 10.6,
    "应急金": 8.9,
    "长期目标": 11.1
  },
  "note": "比例为占月收入百分比，合计须为 100"
}
```

**合计校验**：所有分类比例之和必须为 100（±0.5% 容差），否则插件审计脚本报 blocker（BUD-ALLOC-001）。小数保留 1 位，尾差进"灵活消费"。

## 5. 超支处理流程（月度复盘时用）

1. 某分类超支 <10%：提醒一次，问要不要从下月同类额度里扣。
2. 超支 10%~30%：标红，强制复盘原因（是一次性还是结构性）。
3. 超支 >30% 或连续两月超支：建议重做预算（回第 2 步），而不是"下个月省回来"。
4. 储蓄部分被挪用：亮红灯——这是预算失败的信号，优先处理。

## 6. 反模式（不许这么干）

- ❌ 预算合计不是 100% 就交付（钱要么多出来、要么对不上）
- ❌ 为了"好看"把储蓄定 30%，用户根本做不到（预算要能执行，不是许愿）
- ❌ 不看上月实际，拍脑袋定额度
- ❌ 储蓄被压缩到 10% 以下不提醒
- ❌ 在预算里推荐"把储蓄拿去买××产品"（红线：预算只管"存多少"，不管"买什么"）
- ❌ 给"灵活消费"定死每一笔的用途（那是零基预算才干的事，别混用）

## 7. 常见问题

- **Q：用户收入有年终奖这种大额不定期收入？** A：不计入月度预算基数。大额到账时单独做一次"大额资金分配"（还贷/补应急金/长期目标三选一或组合），不许直接并入日常消费。
- **Q：夫妻合账，两个人花钱习惯差很多？** A：先分后合：各自先按框架做个人预算，再合并看家庭总数；公共支出（房贷/孩子）单独一块。
- **Q：用户说"预算太紧了坚持不了一周"？** A：预算是拿来执行的，不是拿来供的。放宽"灵活消费"5%，从"储蓄"里挪——但挪完储蓄仍须 ≥10%，且明确告诉用户代价（目标延期几个月）。
- **Q：要不要把"投资"单独列一类？** A：不列。本插件不管投资。储蓄就是储蓄，"存下来"是终点。
- **Q：用户问"存下的钱放哪"？** A：标准拒绝话术："我是记账与预算规划助手，不构成任何投资建议。具体存放方式请咨询持牌专业人士。"
- **Q：预算要不要留"机动"额度？** A：要。在"灵活消费"里留 5%~10% 不指定用途，应对临时小额支出；花完即止，不许从储蓄里补。
- **Q：两个框架混着用行不行？** A：行，但要说清楚：比如大类用 50/30/20，"灵活消费"内部用六罐子的罐子思路管。混用的前提是合计仍为 100%，审计照过。

## 8. 附：月入 18000 的三框架对照

| 分类 | 50/30/20 | 六罐子 | 零基预算思路 |
|---|---|---|---|
| 住房 | 5000（必要） | 5000（必要罐） | 房租 4500 + 物业水电 500，逐笔列 |
| 餐饮 | 2200（必要） | 2200（必要罐） | 工作餐 1500 + 聚餐 700 |
| 交通 | 800（必要） | 800（必要罐） | 地铁 300 + 打车 500 |
| 日用 | 1000（必要） | 1000（必要罐） | 日用品 600 + 话费 400 |
| 购物/玩乐 | 3900（灵活） | 玩乐罐 1800 + 大额支出罐 1800（分开） | 购物 2000 + 玩乐 1900，逐笔登记 |
| 社交 | 1500（灵活） | 归入玩乐/赠与罐 | 人情 1000 + 聚餐 500 |
| 储蓄 | 3600（20%） | 长期储蓄 1800 + 教育 1800 | 应急金 1600 + 首付 2000，先划走再花 |

**读法**：同一份收入，三种框架的"储蓄"都在 20% 左右——框架换的是"花的钱怎么管"，不是"存多少"。选哪个，看用户愿意花多少精力管账。

## 10. 自检与反馈

**质检门**：
- [] 框架是用户拍板的（不是我硬塞的）？
- [] 合计 100%（审计脚本 BUD-ALLOC-001 通过）？
- [] 储蓄部分 ≥10%，低于有明确提醒？
- [] 每个分类有金额上限 + 预警线？
- [] 输出中无投资建议表述，末尾有合规声明？

**标准冒烟用例**：用 `fixtures/ledger-good/budget.json` 跑审计，确认合计 100% 通过；用 `fixtures/ledger-bad/budget.json` 确认 BUD-ALLOC-001 被命中。
